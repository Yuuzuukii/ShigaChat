# ShigaChat レスポンシブ画面設計

元の見た目を保持する。1024px以上は原本と同じ表示を基準とし、モバイルでは配置・幅・高さ・折返し・入力操作だけを調整する。原本は変更開始時点のコミット `7e51bcc` である。

## 表示を保持する範囲

- 元のグラデーション、ガラス表現、背景の装飾、配色、影、角丸、アイコン、見出し、本文と注意文を保持する。
- 認証画面の英語UI、元のカード幅、フォーム構成、使用言語の国旗表示を保持する。
- ホームの新しいチャット操作、メッセージと参考Q&A、常時表示の翻訳・要約・わかりやすくする操作を保持する。
- チャット下部の注意文は「※ 本サービスへの質問による個人情報の漏洩に関しては、一切の責任を負いかねます」の全文を表示する。
- カテゴリ別の13色、見出しの下線、質問カード、国旗中心の9言語タブ、画面下の固定戻るボタンを保持する。
- キーワード検索の中央配置の初期画面、検索ボタン、検索語タグ、結果カードを保持する。

## 画面幅と配置

| 幅（CSS px） | ナビゲーション | 元のカテゴリグリッド |
| --- | --- | --- |
| 1024以上 | 常設、展開18rem／縮小3.5rem | 4列（`lg:grid-cols-4`） |
| 768〜1023 | 初期状態は閉じたドロワー | 3列（`md:grid-cols-3`） |
| 320〜767 | 初期状態は閉じたドロワー | 2列（`grid-cols-2`） |

シェルの境界は `DESKTOP_QUERY = "(min-width: 1024px)"` とCSSで揃える。デスクトップの展開状態とモバイルの開閉状態は独立して保持する。モバイルの本文にサイドバー用の余白を残さない。検索入力とボタンは元の`sm`境界（640px）で縦／横に切り替える。

44pxの操作領域と16pxの入力文字、セーフエリア、長いラベルの折返しはモバイル側に適用する。カテゴリ詳細のタブは領域内だけ横スクロールでき、選択中の言語を表示範囲に収める。639px以下では質問カードの内側余白を調整する。

同名の`.js`／`.jsx`は`.js`を正本とし、互換用`.jsx`は再エクスポートにする。ホームの旧featureパスも現行の`components`へ再エクスポートする。単独の`.jsx`部品には重複する`.js`を追加しない。

OutletContextは`language`、`t`、`threadHook`、`isDrawerOpen`、`isMobile`、`scrollContainerRef`を提供する。カテゴリの`?id=`による移動は親の本文スクロール領域を使用し、移動後は`id`だけをURLから除去する。`?lang=`の初期選択・同期と、翻訳後の回答展開状態を維持する。

## 高さ・入力・フォーカス

シェルは`100vh`をフォールバックにして`100dvh`を使用する。モバイルでは`visualViewport.height`を`--app-height`へ反映し、`scale === 1`の値だけ採用する。デスクトップへ移ると高さの上書きを解除する。viewportには`viewport-fit=cover`と`interactive-widget=resizes-content`を指定する。

チャット以外は本文が縦スクロールし、チャットはメッセージ領域がスクロールする。入力はflexの通常配置に置き、短い可視領域ではアクション・補助情報を領域内でスクロールさせる。通知と翻訳選択も可視領域内に収める。

モバイルのチャット可視領域が250px以下の場合、コンテナクエリで上部の重複する新しいチャットボタンを隠し、入力との重なりを防ぐ。同じ操作はサイドバーに保持する。通常高・デスクトップの表示は維持する。通知の透明な領域は操作を遮らず、通知本体の操作だけを受け付ける。

- 入力は内容に応じて最大128pxまで伸縮し、可視領域に応じたCSS上限も持つ。
- デスクトップの通常ポインターはEnterで送信、Shift + Enterで改行する。
- 1024px未満または`pointer: coarse`ではEnterで改行し、送信ボタンを使う。
- IME変換中とキーコード229ではEnter送信しない。処理中の重複送信を防ぎ、空入力の扱いはページの既存検証に従う。
- 検索画面の自動フォーカスはデスクトップに限定し、モバイルでは初期表示でキーボードを開かない。
- ドロワーと確認ダイアログは最上位のモーダル内でTabを循環し、背景を`inert`にする。Escapeで閉じ、元の操作へフォーカスを戻す。
- ラベル、展開状態、通知・エラーの読み上げ属性を付け、`prefers-reduced-motion`に対応する。

## APIと既存動作

| 機能 | 維持するエンドポイント |
| --- | --- |
| 認証 | `/user/token`、`/user/current_user`、`/user/register` |
| 会話 | `/question/get_user_threads`、`/question/get_thread_messages/:id`、`/question/get_answer_stream` |
| スレッド削除・回答アクション | `/question/delete_thread/:id`、`/action/apply` |
| カテゴリ・Q&A・履歴 | `/category/category_translation/:id`、`/category/category/:id?lang=`、`/history/add_history` |
| キーワード検索 | `/keyword/search_with_language?keywords=` |

認証、スレッド選択・名前変更、SSEイベントとスレッドID同期、既存の入力途中の確認を維持する。カテゴリ取得はAbortControllerで古い応答を防ぎ、検索はリクエスト番号で応答の逆転を防ぐ。キーワード検索は変更前から通常ルート・メニューに未登録であり、その状態を維持する。

## 確認と検証記録

復元後のコードで以下を確認した。APIを使用するブラウザー確認は模擬応答を使い、実データを変更していない。

- `CI=true npm test -- --watchAll=false --runInBand`：6スイート・25テスト成功。`npm run lint`、`npm run build`、`git diff --check`も成功。
- 1024px／1440pxで変更前の原本と同じデータ・言語・環境で比較。ログイン・登録・404とカテゴリ詳細はPNG一致。ホームも背景・カード・余白・位置を復元し、輪郭などの微小な画素差だけが残るため、全画像の完全一致とは扱わない。
- 320×568、390×844、768×1024、1024×768、1440×900、844×390でログイン・登録・ホーム・会話・カテゴリ・詳細を確認。長いURLを含めページ全体の横はみ出しとJavaScript例外なし。カテゴリは2／3／4列。
- 320pxで9言語のカテゴリ名と選択中の国旗タブ、モバイルのSSE送信・スレッドID同期・翻訳・ドロワー・ネストした確認ダイアログのフォーカス復元を確認。
- 390×220で長文入力とアクションエラーが重なっても送信が画面内で押せることを確認。レイアウト高さ844pxを保ち、`visualViewport.height`だけ220pxへ縮めた場合も、シェル高さ220px・ヘッダー64px・通知上限77px・送信操作を確認。
- アカウントメニューは通常高と可視高さ220pxの両方で、操作が画面内に収まり押せることを確認。

iOS Safari／Android Chromeの実機確認は未実施。ブラウザーでの疑似ビューポート検証とOSキーボード・セーフエリアの実機確認は区別して記録する。
